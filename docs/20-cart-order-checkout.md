# Rustsky 学习笔记 20 · 购物车与提交订单

顾客加两份热菜，再加一份常温菜，购物车里会看到两行。提交订单时，服务器重新查在售状态和商品价格，写入待付款订单。[课程 Day07 购物车和 Day08 用户下单](https://www.bilibili.com/video/BV1TP411v7v6/)

## 同一项怎么加一份

`POST /user/shoppingCart/add` 接收 `dishId` 或 `setmealId`。如果是菜品，还可以附上 `dishFlavor`。数据库用「用户 ID、商品类型、商品 ID、口味」组成联合唯一索引。

第一次加入时写入一行，数量为 1。第二次加入相同口味时，`INSERT ... ON DUPLICATE KEY UPDATE` 将原有数量加 1。MySQL 在同一条语句里完成插入或更新，两次并发添加也能各加一份。不同口味使用不同的索引值，所以各自保留。

减少数量时用 `SELECT ... FOR UPDATE` 锁住这条购物车记录。数量还有两份及以上就扣一份，只有一份就删除这行。加、减、查、清空都从 JWT 取得用户 ID。

## 为什么订单和明细分两张表

| 表 | 保存的信息 |
| --- | --- |
| `orders` | 订单号、用户、收货信息、支付状态、总价 |
| `order_detail` | 每项商品的名称、单价、口味和数量 |

`order_detail.order_id` 对应 `orders.id`。这是一对多关系。订单保存下单时的地址与商品信息，顾客后来修改收货地址时，之前的订单仍保留原来的地址。

## 按代码顺序看下单事务

1. `submit` 验证登录、请求字段和营业状态。Redis 里的营业开关是关着的，就返回打烊。
2. `checkout` 开启 MySQL 事务，锁定当前用户的购物车并确认地址属于这个用户。
3. 写入订单主表。再从菜品或套餐表读取当前在售价，保存每一项订单明细。若有商品停售，事务回滚，购物车仍保留。
4. 用 MySQL 的 `DECIMAL` 加总「单价 × 数量」，更新订单金额，再清空购物车。事务提交后才返回订单号和金额。

例如两份单价 29.75 元的菜，后端计算 `29.75 × 2 = 59.50` 元。接口忽略客户端传入的金额。当前实现的打包费是 0，支付状态为未支付。预约送达时间按北京时间输入。
