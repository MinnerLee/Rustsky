# Rustsky 学习笔记 15 · 员工状态、编辑和分类管理

本节对应课程第 25–30 集。用管理员打开 [员工管理](http://127.0.0.1:8888/sky/#/employee) 或 [分类管理](http://127.0.0.1:8888/sky/#/category)，也可以从 [Swagger UI](http://127.0.0.1:8888/docs/) 调试。

| 功能 | API | 数据库行为 |
| --- | --- | --- |
| 启用或停用员工 | `POST /api/employee/status/{status}?id=…` | 更新 `status`、最后操作人和时间。`0` 表示停用，`1` 表示启用。 |
| 回显员工资料 | `GET /api/employee/{id}` | 查询一个员工的表单字段，包含工号。 |
| 保存员工编辑 | `PUT /api/employee` | 更新表单字段，工号留空时保留原值。 |
| 维护分类 | `/api/category`、`/api/category/page`、`/api/category/status/{status}` | 支持查询、新增、编辑、启停和删除。新分类默认停用，已有菜品或套餐引用时不能删除。 |

**停用账号需要两处检查。** 登录时 Rust 先看 `employee.status`，停用账号拿不到新令牌。对已经拿到的 JWT，Axum 中间件每次通过签名检查后再查一次员工状态。因此停用时，旧令牌访问受保护接口也会收到 `401`。如果之后重新启用，该账号可以登录，尚未过期的旧令牌也会重新通过状态检查。管理员账号本身不能通过员工管理页面停用或编辑。

**编辑分两次请求。** 前端进入编辑页，先按 ID 读取已有资料。用户点保存时，再发 `PUT` 更新同一条记录。数据库仍检查账号和工号的唯一性。编辑 SQL 只更新表单字段和审计字段，用户可以继续使用原密码。

**分类决定商品放在哪。** 菜品分类和套餐分类共用一张表，用 `type` 区分。管理端分页可以看到全部状态，商品表单用 `/category/list` 获取启用分类。删除前用 SQL 检查有没有商品引用它。

本机的写权限来自 [授权脚本](../db/002-employee-category-grants.sql)。[功能测试](../tools/test-employee-category.ps1) 使用虚构记录验证资料回显、工号修改、停用后令牌失效、重新启用和分类完整流程，结束后清理测试数据。
