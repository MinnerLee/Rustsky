# Rustsky 学习笔记 16 · 菜品、口味与事务

这一段对应 Day03 的审计字段和菜品管理。Rustsky 支持上传图片、添加菜品、按名称或分类分页、回显详情、编辑口味、起售停售和删除。[课程 Day03](https://www.bilibili.com/video/BV1TP411v7v6?p=31)

菜品存在 `dish`，可选口味存在 `dish_flavor`。例如一份火锅在 `dish` 里只有一行，辣度和温度各在 `dish_flavor` 里有一行，通过 `dish_id` 找回它们。保存时，两张表的写入放在同一事务里。修改口味会在事务中删除旧口味并插入新口味，任何一步失败都会回滚，原资料仍可查询。

课程用注解和 AOP 填写 `create_user`、`update_user` 以及时间。Rustsky 从经过 JWT 验证的请求中取出操作人 ID，由 SQL 和业务数据一起写入。新增时两个操作人都填当前管理员，编辑只更新最后操作人和时间。

图片通过 `POST /api/common/upload` 上传。Rust 检查文件头和大小，再保存为本机 `.preview/uploads/` 下的随机文件名。前端将接口返回的 `/uploads/…` 保存到菜品记录，Nginx 按这个路径提供图片。此处用本地文件存储来跑通上传流程。

在 [菜品管理](http://127.0.0.1:8888/sky/#/dish) 测试前，先在 [分类管理](http://127.0.0.1:8888/sky/#/category) 建一个菜品分类并启用。新菜品默认停售。正在售卖或被套餐引用的菜品不能删除。批量删除在一个事务里执行，任意一项不符合条件时整个批次回滚。

本地 [测试脚本](../tools/test-dish.ps1) 验证上传和图片读取、菜品新增、带条件分页、回显、口味替换、分类删除保护和菜品停售后删除。运行前按 [环境笔记](06-reverse-proxy-load-balancing.md) 启动服务，并执行 [菜品授权脚本](../db/003-dish-grants.sql)。
